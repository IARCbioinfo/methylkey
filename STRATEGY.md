## Phase 6: Report Integration (Modular Progressive Builder)
===========================================================

### Architecture

A **progressive, modular report builder** allowing users to construct Quarto-based analysis reports step-by-step without manipulating `.qmd` or YAML files directly.

**Core Components:**

1. **MethylkeyReport S4 Class**
   - Tracks report metadata, steps, caching strategy
   - Supports multiple reports in same folder via `report_id`
   - Manages project structure and file generation

2. **Progressive Step Functions**
   - `add_report_data_loading()` - Data loading chapter
   - `add_report_qc()` - Quality control chapter
   - `add_report_group_control()` - Exploratory analysis (PCA, MDS)
   - `add_report_model_analysis()` - Differential analysis by model
   - `add_report_subgroup()` - Subgroup-specific analysis

3. **Cache & Rebuild Management**
   - `rebuild_report_step()` - Force rerun specific step without recomputing others
   - `clear_report_cache()` - Clean Quarto cache and intermediate files
   - Incremental rendering: only modified/new pages recalculated

4. **Report Templates** (inst/templates/)
   - `.qmd.template` files with placeholder injection (e.g., `{{IDAT_PATH}}`, `{{MODEL}}`)
   - `_quarto.yml.template` - Dynamic YAML generation
   - Template-based approach: scalable and maintainable

### Key Features

✨ **Incremental Workflow**
- Add steps one at a time without recalculating previous work
- Add multiple models independently (each new model = new chapter)
- Quarto handles caching and selective rerun

🎯 **Multi-Report Support**
- `report_id` parameter isolates multiple reports in same folder
- Prevents file/cache collisions
- Each report has dedicated subdirectory or prefixed files

🔧 **User Control**
- Explicit rerun: `rebuild_report_step(report, "models", force = TRUE)`
- Cache cleanup: `clear_report_cache(report)` for fresh starts
- Both essential for iterative refinement and troubleshooting

### Usage Examples (Post-Implementation)

**Example 1: Basic Progressive Workflow**
```r
report <- create_methylkey_report(
  project_dir = "~/my_analysis",
  report_id = "exp_001",
  idat_path = "/data/idats/",
  sample_sheet_path = "samples.csv",
  title = "Methylation Analysis",
  author = "My Lab"
)

# Add steps progressively
report <- report |>
  add_report_data_loading(prep = "TQCDPB", ncore = 4) |>
  add_report_qc(groups = c("group", "age", "sentrix_id")) |>
  add_report_group_control(correction = "raw", exclude_xy = FALSE)

# User refines analysis parameters, then adds model
report <- report |>
  add_report_model_analysis(model = "~group", intercept = "WT", dmrtools = c("dmrcate", "ipdmr"))

# Add second model without recalculating earlier steps
report <- report |>
  add_report_model_analysis(model = "~group+age", intercept = "WT", dmrtools = c("dmrcate"))

# If needed, rebuild one step and clean cache
report <- rebuild_report_step(report, step = "group_control", force = TRUE)
clear_report_cache(report)

# Render everything
render_report(report)
```

**Example 2: Multiple Reports in Same Folder**
```r
# Report 1: raw data analysis
report1 <- create_methylkey_report("~/project", report_id = "raw", ...) |>
  add_report_data_loading(...) |>
  add_report_qc(...)

# Report 2: batch-corrected analysis
report2 <- create_methylkey_report("~/project", report_id = "sva_corrected", ...) |>
  add_report_data_loading(prep = "TQCDPB", ...) |>
  add_report_qc(...) |>
  add_report_group_control(correction = "sva", ...)

# Both reports coexist without conflict
render_report(report1)
render_report(report2)
```
